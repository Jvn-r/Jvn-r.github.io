Open-ended 1 — Exposing an app with a NodePort Service

Terminal-friendly lab notes for w3m.

Lab indexLab 1Lab 2Lab 3Lab 4Lab 5Lab 6Lab 7Lab 8Lab 9Lab 10

Goal: expose the Lab 8 Deployment with a NodePort Service, reach it from outside the cluster, break the Service by pointing its selector at a label no Pod has, then fix it. This builds on Lab 8, so Steps 4 and 5 recreate the image and the Deployment.

Step 0 — Install Docker (fresh machine)

sudo apt-get update
sudo apt-get install -y docker.io
sudo systemctl enable --now docker
sudo usermod -aG docker $USER
newgrp docker
docker --version

Step 1 — Install kubectl

curl -LO "https://dl.k8s.io/release/$(curl -L -s https://dl.k8s.io/release/stable.txt)/bin/linux/amd64/kubectl"
sudo install -o root -g root -m 0755 kubectl /usr/local/bin/kubectl
rm kubectl
kubectl version --client

Step 2 — Install Minikube

curl -LO https://github.com/kubernetes/minikube/releases/latest/download/minikube-linux-amd64
sudo install minikube-linux-amd64 /usr/local/bin/minikube
rm minikube-linux-amd64
minikube version

Step 3 — Start the cluster

minikube start --driver=docker
kubectl get nodes

Step 4 — Create the app, build the image and load it into Minikube

mkdir -p ~/oe1 && cd ~/oe1

cat > app.py <<'EOF'
from flask import Flask

app = Flask(__name__)

@app.route("/")
def home():
    return "Hello from the CCAI Docker Lab!"

@app.route("/health")
def health():
    return {"status": "healthy"}

if __name__ == "__main__":
    app.run(host="0.0.0.0", port=5000)
EOF

echo "Flask==3.1.0" > requirements.txt

cat > Dockerfile <<'EOF'
FROM python:3.12-slim
WORKDIR /app
RUN apt-get update && \
    apt-get install -y bash procps curl && \
    rm -rf /var/lib/apt/lists/*
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
EXPOSE 5000
CMD ["python", "app.py"]
EOF

docker build -t myapp:v1 .
minikube image load myapp:v1

Step 5 — Create and apply the Lab 8 Deployment

cat > deployment.yaml <<'EOF'
apiVersion: apps/v1
kind: Deployment
metadata:
  name: myapp-deployment
spec:
  replicas: 2
  selector:
    matchLabels:
      app: myapp
  template:
    metadata:
      labels:
        app: myapp
    spec:
      containers:
      - name: myapp
        image: myapp:v1
        imagePullPolicy: Never
        ports:
        - containerPort: 5000
EOF

kubectl apply -f deployment.yaml
kubectl get pods

Expected: two Pods, Running within a few seconds.

Step 6 — Create the Service manifest service.yaml

cat > service.yaml <<'EOF'
apiVersion: v1
kind: Service
metadata:
  name: myapp-service
spec:
  type: NodePort
  selector:
    app: myapp
  ports:
  - port: 5000
    targetPort: 5000
EOF

selector must match the Pod label app: myapp from the Deployment. port is the Service's own port, targetPort is the container port. With no nodePort given, Kubernetes assigns one from 30000 to 32767.

Step 7 — Apply the Service and inspect the assigned NodePort

kubectl apply -f service.yaml
kubectl get svc myapp-service
kubectl get endpoints myapp-service

Expected: the PORT(S) column reads like 5000:31234/TCP, where 31234 is the NodePort. The endpoints list shows two Pod IPs on port 5000.

Step 8 — Access the app from outside the cluster

NODE_IP=$(minikube ip)
NODE_PORT=$(kubectl get svc myapp-service -o jsonpath='{.spec.ports[0].nodePort}')
echo "$NODE_IP:$NODE_PORT"
curl http://$NODE_IP:$NODE_PORT
curl http://$NODE_IP:$NODE_PORT/health

Expected: Hello from the CCAI Docker Lab! and {"status":"healthy"}. The two variables only exist in this terminal. If the node IP isn't reachable (Docker driver on Windows or macOS), run minikube service myapp-service --url and curl the URL it prints.

Step 9 — Point the selector at a label no Pod has

sed -i 's/app: myapp/app: wrongapp/' service.yaml
kubectl apply -f service.yaml
kubectl get endpoints myapp-service
curl --max-time 5 http://$NODE_IP:$NODE_PORT

Expected: ENDPOINTS shows <none> and curl fails (connection refused or timeout). The Pods are healthy, but the Service selects none of them, so no traffic is routed. You can also edit service.yaml in nano instead of using sed.

Step 10 — Correct the selector and confirm access is back

sed -i 's/app: wrongapp/app: myapp/' service.yaml
kubectl apply -f service.yaml
kubectl get endpoints myapp-service
curl http://$NODE_IP:$NODE_PORT

Expected: two endpoints again and the greeting is returned on the same NodePort.

Cleanup

kubectl delete -f service.yaml -f deployment.yaml
minikube stop
