Lab 6 — Multi-container app with Docker Compose

Terminal-friendly lab notes for w3m.

Lab indexLab 1Lab 2Lab 3Lab 4Lab 5Lab 6Lab 7Lab 8Lab 9Lab 10

Goal: define a web service and a database in one docker-compose.yml, start them together, read one service's logs, open a shell in a service and tear everything down.

Step 0 — Install Docker and the Compose plugin (fresh machine)

sudo apt-get update
sudo apt-get install -y docker.io docker-compose-v2
sudo systemctl enable --now docker
sudo usermod -aG docker $USER
newgrp docker
docker --version
docker compose version

docker compose (with a space) is Compose v2, installed as a Docker plugin. If the docker-compose-v2 package isn't found, install Docker with curl -fsSL https://get.docker.com | sudo sh instead of docker.io; that script includes the plugin.

Step 1 — Create the project: app, requirements and Dockerfile

The web service builds from a Dockerfile (build: .), so this folder needs the Lab 2 Dockerfile and requirements.txt plus a simple app.py.

mkdir -p ~/myapp-compose && cd ~/myapp-compose

cat > app.py <<'EOF'
from flask import Flask

app = Flask(__name__)

@app.route("/")
def home():
    return "Docker Compose application is running!"

if __name__ == "__main__":
    app.run(host="0.0.0.0", port=5000)
EOF

echo "Flask==3.1.0" > requirements.txt

cat > Dockerfile <<'EOF'
FROM python:3.12-slim
WORKDIR /app
RUN apt-get update && \
    apt-get install -y bash procps curl && \
    rm -rf /var/lib/apt/lists/*
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
EXPOSE 5000
CMD ["python", "app.py"]
EOF

Step 2 — Create docker-compose.yml

cat > docker-compose.yml <<'EOF'
services:
  web:
    build: .
    ports:
      - "5000:5000"
    depends_on:
      - database

  database:
    image: postgres:15
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: admin123
      POSTGRES_DB: labdb
    volumes:
      - compose_db_data:/var/lib/postgresql/data

volumes:
  compose_db_data:
EOF

depends_on makes Compose start database before web. It waits for the container to start, not for Postgres to be ready. compose_db_data is a named volume that keeps the database files.

Step 3 — Start the stack

docker compose up -d

The first run builds the web image and pulls postgres:15, so it takes a minute.

Step 4 — Verify both services are running

docker compose ps

Expected: web and database both listed as running.

Step 5 — Test the web service

curl http://localhost:5000

Expected: Docker Compose application is running!

Step 6 — View and follow the web service logs

docker compose logs web
docker compose logs -f web

Press Ctrl+C to stop following. Run curl http://localhost:5000 in a second terminal to see requests appear.

Step 7 — Inspect the running web service

docker compose exec web /bin/sh

Inside the container:

ls
exit

Expected: Dockerfile app.py docker-compose.yml requirements.txt, because COPY . . copied the whole folder into the image.

Step 8 — Bring the stack down

docker compose down
docker compose ps

Expected: docker compose ps shows an empty list.

Step 9 — Verify the containers and network are gone

docker ps -a
docker network ls
docker volume ls

Expected: both containers and the Compose network (myapp-compose_default) are gone. The named volume (myapp-compose_compose_db_data) is still listed, because down keeps volumes unless you add -v.

Cleanup

docker compose down -v
